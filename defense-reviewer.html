30-SECOND ANSWER

What is RentWise?

RentWise is a rental-management system for Ka Domeng Talipapa. Guests find stalls, tenants manage rent, admins handle daily work, and the owner monitors the business.

MAIN PROBLEM

What does it solve?

It replaces scattered paper and manual records with one organized system. Each user sees only the tools needed for their role.

SECURITY

How is it protected?

Firebase Authentication checks identity. Firestore Rules and Cloud Functions check what each user is allowed to do. Hiding a screen is not the main security.

AR FEATURE

What is AR for?

AR lets a guest place 3D objects on a detected floor and preview a stall design. It is not used for market navigation.

Login

User signs in → Firebase checks the account → the app reads the role → security rules allow only permitted data.

Tenant payment

Tenant chooses a payment method → PayMongo opens checkout → payment is recorded → admin verifies it → approved information appears in history and summaries.

Admin to owner

Admin makes an important change → owner receives a report → owner acknowledges or reviews it → the result is saved.

Rent reminders

The system checks due rent at the configured time. It creates an in-app notification and tries to send an SMS through Semaphore.

Guest stall map

The website requests only safe public stall details. It shows occupied and unoccupied stalls without exposing private tenant data.

Tenant AR button

Tenant taps AR → RentWise opens the Guest AR page in a Chrome Custom Tab → Chrome connects WebXR to ARCore → Back returns to the Tenant dashboard.

AR placement

The phone detects a stable floor. The marker turns green when placement is safe, then the guest places and arranges a 3D object.

Core technologies

  • React Native + Expo: shared mobile development and Android APK builds.
  • Expo Router: file-based navigation in the apps and guest web module.
  • Expo WebBrowser + Chrome Custom Tabs: opens Tenant AR through Chrome so WebXR can use ARCore and Back can return to RentWise.
  • Firebase Authentication: account identity and login.
  • Cloud Firestore: the deployed NoSQL source of truth.
  • Cloud Functions: trusted validation, scheduled tasks, recovery, and public API boundaries.
  • WebXR + Three.js: browser-based AR surface detection and GLB rendering.
  • PayMongo: sandbox online-payment flow.
  • Semaphore: SMS delivery when configured.

Why React Native + Expo?

One TypeScript codebase is faster to build and maintain than separate Android and iOS apps. Expo also simplifies testing and APK builds.

Why Firebase?

Firebase combines login, database, security, storage, and backend tools. It requires less server maintenance than a self-managed backend.

Why Firestore?

Firestore provides real-time updates and server-enforced rules, which fit our connected multi-role system better than a traditional SQL setup.

Why Cloud Functions?

They run secure backend tasks without maintaining a dedicated server.

Why WebXR + Three.js?

Guests can use AR through a supported browser without installing another app. Unity offers wider AR support but requires a separate application.

Why PayMongo?

It supports Philippine payment methods such as GCash and Maya and provides a sandbox for testing.

Why Semaphore?

It is designed for Philippine SMS and fits our reminder and OTP requirements better than international alternatives.

Why Expo Router?

File-based routes make the applications easier to organize than a large manual navigation setup.

How updates are released

Mobile: code → check errors → EAS Build → Android APK.

Website: code → Vercel deployment → rentwise-kadomeng.site.

Backend: code → Firebase deployment → Functions and Security Rules.

Runtime request pipeline

User action → app validates input → Firebase Auth supplies identity when required → Firestore Rules or a Cloud Function validates authorization and data → Firestore stores or reads data → the interface receives the result and updates.

Where Postman fits

Postman is an optional API-testing tool. It sends sample HTTP requests and displays responses. It is useful for backend testing, but it is not required to run RentWise and does not replace application, rules, or real-device testing.

Before presenting

Honest limitations

  • Immersive WebXR placement primarily targets supported Android Chrome devices.
  • PayMongo must be described accurately as test/sandbox unless production credentials are confirmed.
  • The system currently depends on Firebase; MongoDB failover is not part of the deployed client path.
  • Testing is structured and device-based, but there is no complete automated test suite.
  • AR validates surface quality but cannot perfectly identify every elevated flat surface as “not the floor.”

Current-code corrections

  • Semaphore is a real shared SMS implementation for reminders and password-reset codes, with Philippine-number normalization, supported wrapped/direct response parsing, up to three attempts, and masked sms_logs auditing.
  • A Semaphore accepted result proves provider acceptance, not handset delivery or reading.
  • Reminder claims are atomic per tenant/billing period; failed SMS claims are removed for a later retry, and in-app notifications remain independent of SMS success.
  • The tenant payment service currently calls the Vercel create-payment-intent endpoint.
  • Firestore Rules explicitly prevent self-updates to role, status, price, and payment schedule.
  • The guest page no longer reads complete stall documents anonymously. A rate-limited callable returns only an approved public field list.
  • Guest contact and AR-event writes are validated and rate-limited by Cloud Functions.
