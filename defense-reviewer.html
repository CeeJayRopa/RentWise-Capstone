30-SECOND VERSION

What is RentWise?

RentWise is a four-module rental-management system for Ka Domeng Talipapa. It connects public stall discovery, tenant payments, administrator operations, and owner oversight through one secured Firebase backend.

CORE VALUE

What problem does it solve?

It replaces disconnected manual records with centralized, role-specific workflows. Tenants see what they owe, admins manage daily operations, owners review changes, and guests see live stall information.

SAY THIS CLEARLY

Security boundary

Navigation hides irrelevant screens for usability. Real authorization is enforced server-side by Firestore Security Rules and privileged Cloud Functions.

DIFFERENTIATOR

AR purpose

The guest AR feature is for designing a stall: users arrange supported 3D objects and preview the layout on a detected floor surface. It is not a market-navigation feature.

Mark each block complete. Do not spend the day memorizing paragraphs—practice explaining flows in your own words.

Authentication and authorization

Firebase Auth signs the user in → the app reads users/{uid} → role determines routing → Firestore Rules independently allow or reject every database request.

Tenant payment

Tenant chooses GCash/Maya → tenant app calls the Vercel PayMongo payment-intent API → PayMongo returns a redirect → payment is recorded → admin verifies → approved data updates dashboards/history.

Admin to owner

Admin records a significant change → an update and notification are created → owner reviews → approval state is stored → reports and notifications reflect the decision.

Rent reminders

Cloud Scheduler runs the reminder function → billing history is checked → duplicates are avoided → notification is created → push/Semaphore SMS delivery is attempted with retries and audit logs.

Guest stall map

Public page calls getPublicStalls → the Cloud Function validates and rate-limits the request → only safe public stall fields are returned → the page refreshes occupancy data every 15 seconds → selecting a stall opens its public rental information.

AR placement

Three.js loads a GLB → WebXR hit testing finds a candidate surface → plane/depth/stability and wall-clearance checks validate it → reticle turns green → object is placed and can be arranged.

Core technologies

  • React Native + Expo: shared mobile development and Android APK builds.
  • Expo Router: file-based navigation in the apps and guest web module.
  • Firebase Authentication: account identity and login.
  • Cloud Firestore: the deployed NoSQL source of truth.
  • Cloud Functions: trusted validation, scheduled tasks, recovery, and public API boundaries.
  • WebXR + Three.js: browser-based AR surface detection and GLB rendering.
  • PayMongo: sandbox online-payment flow.
  • Semaphore: SMS delivery when configured.

Deployment pipeline

Mobile: source code → TypeScript checks → EAS Build → downloadable Android APK.

Guest website: source code → Git commit/push → connected web deployment → e-kadomeng.site.

Backend: TypeScript build → Firebase CLI deploy → Cloud Functions and Firestore Rules.

Runtime request pipeline

User action → app validates input → Firebase Auth supplies identity when required → Firestore Rules or a Cloud Function validates authorization and data → Firestore stores or reads data → the interface receives the result and updates.

Where Postman fits

Postman is an optional API-testing tool. It sends sample HTTP requests and displays responses. It is useful for backend testing, but it is not required to run RentWise and does not replace application, rules, or real-device testing.

Before presenting

Honest limitations

  • Immersive WebXR placement primarily targets supported Android Chrome devices.
  • PayMongo must be described accurately as test/sandbox unless production credentials are confirmed.
  • The system currently depends on Firebase; MongoDB failover is not part of the deployed client path.
  • Testing is structured and device-based, but there is no complete automated test suite.
  • AR validates surface quality but cannot perfectly identify every elevated flat surface as “not the floor.”

Current-code corrections

  • Semaphore is a real implementation with number normalization, up to three attempts, and sms_logs auditing when the secret is configured.
  • The tenant payment service currently calls the Vercel create-payment-intent endpoint.
  • Firestore Rules explicitly prevent self-updates to role, status, price, and payment schedule.
  • The guest page no longer reads complete stall documents anonymously. A rate-limited callable returns only an approved public field list.
  • Guest contact and AR-event writes are validated and rate-limited by Cloud Functions.
