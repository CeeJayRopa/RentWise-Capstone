3. AR: no way to tell "the real floor" from "any flat elevated surface"
---------------------------------------------------------------------------
File: rentwise-guest/features/ar/ARSessionScene.ts
Status: diagnosed, not implemented (0% coded).
Every current placement check (tilt angle, plane classification/area,
stability, wall clearance) verifies a surface is flat, real, stable, and not
near a wall - none of them verify it's actually at floor height. A flat
tabletop, shelf, or the top of a wrapped package can pass every check and
register as placeable, the same as real floor. Confirmed via device testing.
The problem is fully understood and candidate fix directions exist, but no
code has been written toward any of them:
  - Track the lowest confidently-detected plane per session as "the floor"
    reference, reject flat surfaces well above it.
  - Use the depth sensor (where available) to reason about height above
    true ground, not just distance-agreement.
  - Accept as an inherent limitation of markerless AR without a fixed
    reference point.


4. AR: reticle flicker only fixed for the wall-clearance check specifically
--------------------------------------------------------------------------
File: rentwise-guest/features/ar/ARSessionScene.ts
Status: pattern proven elsewhere, not applied here; not confirmed to be a
real problem.
Note: field testing confirms the wall-clearance debounce fix itself (fast
floor scanning, correct wall-proximity blocking, no more flicker there) is
working well. That's a different, already-fixed check from the one this
item describes (classifyPlaneValidity's own thresholds) - unclear yet
whether that specific case was part of testing.
The green/red flicker QA reported near walls was fixed by debouncing
isTooCloseToWall() (WALL_CLEARANCE_DEBOUNCE_FRAMES). classifyPlaneValidity()
has the same theoretical vulnerability at its own thresholds (plane area,
perpendicular distance) - recomputed fresh every frame, no hysteresis.
Applying the same debounce pattern here would be quick and low-risk if
needed, since the mechanism already exists and works elsewhere in the file.
However, this has never actually been reported as a real problem away from
walls - only flagged as a theoretical possibility. May not need doing at all
unless it shows up in testing.
